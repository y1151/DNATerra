# DNATerra Input Data

This directory contains the built-in simulator noise library. The library includes 17 samples, with noise profiles characterized from public sequencing datasets.

These profiles are empirical dataset-level profiles, not mechanistic models of synthesis, PCR or sequencing processes. Sample names that contain PCR conditions identify the measured dataset only. They cannot be used to derive unmeasured PCR cycles or to automatically predict another PCR condition. Use each profile as an independent `--method`, or create a new profile from your own data with the self-update workflow.

The built-in profiles come from three high-throughput chip-based synthesis platforms followed by high-throughput next-generation sequencing. The sample set covers full reading, random access, several PCR-cycle conditions and different aging-time conditions.

Each built-in sample is represented by four `.npz` files:

- `read_coverage_depth_<SampleID>.npz`
- `per_position_error_rates_<SampleID>.npz`
- `error_bias_<SampleID>.npz`
- `error_bias_kmer_<SampleID>.npz`

Use the `Sample ID` value as the simulator `--method`.

## Profile Definitions

Average read depth is the average number of sequencing reads observed per reference sequence. In the profile table, it is calculated across the reference sequence set for each dataset.

The recommended read-depth distribution describes how read counts vary among reference sequences. For the built-in profiles, nine candidate distributions were evaluated with AIC, QQ-plot behavior, mean error and CV error, and the most suitable distribution is reported in the table. During simulation, DNATerra uses the selected distribution name together with average read depth and CV to derive the distribution parameters and then sample read depth for each reference sequence. For newly generated profiles from `sequencing_statistics.py`, the `BestDistribution` field is selected automatically by AIC.

Position-specific error rates are sequencing-read error rates estimated from alignments to equal-length reference sequences. The reference sequences define only the coordinate system used to assign read observations to positions. For each position, both the numerator and denominator come from the sequencing reads: DNATerra counts substitution, insertion and deletion events observed in aligned reads at that position, and divides each count by the number of read bases from aligned sequencing reads that cover that position. The `.npz` profile stores these per-position sequencing-read error rates. The summary-table error-rate columns report dataset-level sequencing-read error rates as total observed substitution, insertion or deletion events divided by total covered read bases, expressed in `10^-3 nt^-1`.

Single-base bias describes base-level preferences independent of sequence context. The substitution matrix records the relative probability of changing each original base to each possible post-error base and is normalized by original base. The insertion vector records the relative abundance of inserted A/T/C/G bases and is normalized before simulation. Deletion events are determined by the sampled deletion positions and the reference base at those positions; the single-base deletion matrix is reported from statistics but is not used to choose deletion bases during simulation.

K-mer context bias describes local sequence-context effects. For substitution and insertion, DNATerra uses the previous three reference bases plus the current reference base as context, then samples the post-substitution base or inserted base from normalized context-specific probabilities. K-mer deletion statistics are also generated by the self-update workflow, but current simulation determines deletion events from the position-specific deletion rate rather than dynamically choosing deletion bases from a k-mer deletion preference.

## Test Sequences

The `seq_n*_l150.fasta` files are randomly generated DNA sequences for simulator testing. The `n*` value gives the number of 150 bp reference sequences in the file.

## Self-update Test Data

The following files are included to test the self-update workflow:

- `test.fasta`: reference sequences from a biochemical experiment
- `test_1.fq`: the first 2,500 sequencing reads from the same experiment
- `test_2.fq`: the first 2,500 paired-end sequencing reads from the same experiment
